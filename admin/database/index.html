    Database & Migrations

    Both chakra-license-hub and chakra-license-server share a single PostgreSQL database (Neon managed Postgres in production).

    Core tables

    licenses

    The primary table. One row per project.

    Column Type Description
    id serial Primary key
    name text Project display name
    company text Customer company (legacy; now superseded by organizations)
    token_hash text SHA-256 of the licence key
    token_prefix text First 16 chars (display only)
    is_active boolean Whether the licence accepts sessions
    package text Service tier (must match packages.yaml)
    channels text Comma-separated channel list
    pipelines text Comma-separated pipeline list
    used_minutes integer Cumulative minutes across all calls
    daily_limit_seconds integer Per-caller daily cap
    limit_warning_seconds integer Warning threshold
    gemini_voice text Voice name for Gemini Live
    greeting_mode text recorded / auto / empty
    greeting_id text ID of the uploaded greeting clip
    greeting_text text Transcript of the greeting
    google_access text gateway or empty
    gemini_api_key_enc bytea Encrypted Gemini API key (NaCl secretbox)

    organizations

    Column Type Description
    id serial Primary key
    name text Organisation display name
    package text Package applied to all projects
    email text Organisation user login
    password_hash text scrypt hash

    call_usage

    Hourly voice call metrics. Composite unique key on (license_id, hour, pipeline).

    chat_usage

    Hourly chat metrics. Composite unique key on (license_id, hour).

    Running migrations

    Migrations live in chakra-license-server/migrations/. They are plain SQL files applied in numeric order.

    cd chakra-license-server
python init_db.py   # creates all tables and applies migration 001 automatically

    Migration 001 — Hash tokens

    001_hash_tokens.sql — Additive and safe to run on a live database.

    • Adds token_hash and token_prefix columns to licenses.
    • Hashes every existing plaintext key into token_hash.
    • Existing client keys continue to work (the server falls back to plaintext during the transition).

    Migration 002 — Drop plaintext tokens

    002_drop_plaintext_tokens.sql — Irreversible. Run only after all services are updated.

    • Drops the token (plaintext) column from licenses.
    • After this, no plaintext key can ever be read back.

    Irreversible

    Run migration 002 only after:

    1. The new license server and hub are deployed and verified.
    2. All running chakra-convai instances have been restarted with their new (hashed-lookup compatible) keys.

    One-time steps for the existing database

    Required for security

    These steps address a historical credential leak where DATABASE_URL was committed to the repository.

    1. Rotate the Neon database password.
      The old password is in git history and must be treated as public.
      After rotating, update DATABASE_URL in:

      • chakra-license-server/.env
      • chakra-license-hub/.env.local
      • chakra-gpu-fleet environment

    2. Apply migration 001 (run python init_db.py or execute the SQL directly).
      This adds the hash columns and populates them. Additive — safe on a live database.

    3. Deploy the new admin hub, license server, and speech gateway.

    4. Apply migration 002 (once all deployments are verified).
      Drops the plaintext token column.

    Local development database

    # Start a local Postgres instance (Docker)
docker run -d -p 5432:5432 -e POSTGRES_PASSWORD=dev postgres:16

# Set DATABASE_URL
export DATABASE_URL=postgresql://postgres:dev@localhost:5432/chakra_admin

# Initialise
python chakra-license-server/init_db.py
